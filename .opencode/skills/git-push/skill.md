# git-push Skill

将当前分支的代码通过 git add → git commit → git push 推送到远程仓库。

## 前置条件

- 当前目录是 git 仓库
- 远程仓库已配置（`git remote -v` 可查看）
- 远端已有 `test-ralph` 分支

## 工作流程

### 第1步：git status 查看当前状态

运行 `git status` 展示当前工作区状态，让用户了解有哪些文件已修改、新增或删除。

> 此步骤自动执行，无需用户确认

### 第2步：用户确认要添加的文件

询问用户需要添加哪些文件。展示 git status 的输出，让用户指定要 add 的文件。

用户指定后，执行 `git add <文件路径>`。

> 需要用户确认的步骤：**是**——用户选择要 add 的文件

### 第3步：用户确认 commit 信息

询问用户 commit message 内容。如果用户没有提供，根据修改内容简要总结后让用户确认或修改。

用户确认 message 后，执行 `git commit -m "<message>"`。

> 需要用户确认的步骤：**是**——用户提供或确认 commit message

### 第4步：用户授权推送

**推送需要用户明确授权**。在执行 `git push origin test-ralph` 之前，必须：

1. 展示将要推送的 commit 内容（`git log --oneline -3`）
2. 询问用户是否确认推送到远端
3. 获得用户明确同意后执行推送

> 需要用户明确授权的步骤：**是**——推送风险操作

### 第5步：推送结果

推送完成后，向用户报告结果：
- 成功：显示推送的 commit 和远端分支
- 失败：显示错误信息并建议处理方式

## 集成到 Ralph 循环

所有用户故事完成且编译通过后，询问用户："代码已完成，是否需要通过 git 提交并推送到远端？" 如果用户确认，调用 git-push 技能。

## 错误处理

| 错误场景 | 处理方式 |
|---------|---------|
| git add 失败（文件不存在） | 提示用户检查文件路径 |
| commit 失败（空提交、钩子拒绝） | 显示错误，询问用户如何处理 |
| push 失败（网络、权限、冲突） | 显示错误，询问重试或手动处理 |
| 远端正被其他人推送 | 提示拉取最新代码再推送 |
