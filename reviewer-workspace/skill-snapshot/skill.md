# Code Reviewer Skill for Ralph Loop

## 概述

此 skill 在每轮 Ralph 循环完成后，对代码进行独立检视。只有检视通过，才能进入下一轮循环；否则需要修改代码并重新检视。

## 触发条件

当 Ralph 循环完成一轮迭代后，自动触发此 skill：
- Ralph 子 agent 完成故事实现并更新 prd.json
- 启动检视流程

也可以手动触发：
- "检视代码"
- "审查当前修改"
- "检查代码质量"

## 核心原则

1. **独立检视** - 使用 `task` 工具启动全新的检视 sub-agent
2. **严格把关** - 检视不通过不允许进入下一轮
3. **闭环反馈** - 检视不通过时，启动修复 sub-agent 并重新检视
4. **只读评估** - 检视 agent 只评估不修改代码

## 检视流程

**由主 agent（你）控制检视流程：**

```
检视循环:
  1. 读取当前状态
      - 读取 prd.json，获取刚完成的故事 ID
      - 读取 progress.txt，了解实现内容
      - 查看 git diff 或最近的文件变更
  
  2. 启动检视 sub-agent:
      子agent类型: general
      任务描述: "检视 US-XXX 的代码实现"
      任务内容: 见下方"检视 Agent 任务指令"
      （不指定 task_id，确保全新上下文）
  
  3. 等待检视 agent 完成
  
  4. 解析检视结果:
      - 如果通过 → 允许进入下一轮 Ralph 循环
      - 如果未通过 → 启动修复流程
  
  5. 修复流程:
      - 启动修复 sub-agent（全新上下文）
      - 传递检视反馈和修复指令
      - 修复完成后，重新启动检视（回到步骤 1）
      - 最多重试 3 次
  
  6. 如果 3 次修复仍未通过:
      - 记录问题到 progress.txt
      - 将故事 passes 设为 true 并添加 notes 说明检视失败
      - 继续下一轮（或停止）
```

## 检视 Agent 任务指令

每次启动检视 agent 时，传递以下指令：

```
你是一个专业的代码检视 agent，正在检视 Ralph 循环最近一轮的代码实现。

## 重要：你是全新实例
- 你没有任何之前迭代的记忆
- 只通过以下文件获取上下文：
  - prd.json（查看刚完成的故事的验收标准）
  - progress.txt（了解实现内容）
  - git diff 或变更的文件

## 你的任务

1. **了解验收标准**
   - 读取 prd.json，找到刚完成的故事（passes 刚设为 true）
   - 记录该故事的 acceptanceCriteria

2. **查看代码变更**
   - 使用 git diff HEAD~1 查看最近一次提交或变更
   - 或读取 progress.txt 中记录的文件变更列表
   - 重点检查与故事相关的文件

3. **执行检视**
    检查以下方面：
    
    a. **功能完整性**
       - 是否实现了所有验收标准？
       - 是否有遗漏的功能点？
    
    b. **代码质量**
       - 是否遵循现有代码模式？
       - 是否有明显的 anti-pattern？
       - 是否有未使用的代码或死代码？
    
    c. **边界情况**
       - 是否处理了错误情况？
       - 是否有潜在的 null/undefined 问题？
    
    d. **一致性**
       - 命名是否一致？
       - 格式是否遵循项目规范？

4. **输出检视结果**
    必须以以下格式输出结果：
    
    ```
    ## 检视结果
    
    **状态：** PASS 或 FAIL
    
    **检视故事：** US-XXX - [故事标题]
    
    **验收标准检查：**
    - [ ] 标准1 - [通过/未通过] - [说明]
    - [ ] 标准2 - [通过/未通过] - [说明]
    
    **代码质量检查：**
    - 代码模式：[符合/不符合] - [说明]
    - 边界处理：[充分/不充分] - [说明]
    - 一致性：[良好/有问题] - [说明]
    
    **问题列表：**（如果 FAIL）
    1. [问题描述]
    2. [问题描述]
    
    **修复建议：**（如果 FAIL）
    - [建议1]
    - [建议2]
    ```
    
    如果状态为 PASS，只需输出检视结果即可结束。
    如果状态为 FAIL，必须提供详细的问题列表和修复建议。
```

## 修复 Agent 任务指令

当检视未通过时，启动修复 agent：

```
你是一个代码修复 agent，正在修复检视中发现的问题。

## 重要：你是全新实例
- 你没有任何之前迭代的记忆
- 通过以下文件获取上下文：
  - prd.json（了解故事要求）
  - progress.txt（了解之前的实现）
  - 检视反馈（见下方）

## 检视反馈

[粘贴检视 agent 的输出，包括问题列表和修复建议]

## 你的任务

1. **理解问题**
   - 阅读检视反馈中的问题列表
   - 理解每个问题的上下文

2. **修复代码**
   - 根据修复建议修改代码
   - 只修复检视发现的问题，不要做其他改动
   - 遵循现有代码模式

3. **验证修复**
   - 确认每个问题都已修复
   - 确保没有引入新问题

4. **更新进度**
   - 追加到 progress.txt：
     ```
     ## [时间] - 修复 US-XXX
     - 修复内容：[列出修复的问题]
     - 修改文件：[列表]
     ---
     ```

5. **结束**
   - 简单说明修复了哪些问题
   - 不需要输出特殊格式
```

## 检视结果处理

### 检视通过（PASS）

向用户汇报并允许进入下一轮：
```
✓ US-001 检视通过
  - 所有验收标准已满足
  - 代码质量良好
  → 进入下一轮循环
```

### 检视未通过（FAIL）

启动修复流程：
```
✗ US-001 检视未通过
  问题：
  - [问题1]
  - [问题2]
  
  启动修复 agent...
```

修复完成后，重新检视：
```
  修复完成，重新检视...
  [重新启动检视 agent]
```

如果 3 次修复仍未通过：
```
✗ US-001 检视失败（已达最大重试次数）
  问题：[最后的问题列表]
  
  记录到 progress.txt，继续下一轮...
```

## 与 Ralph Skill 的集成

修改 Ralph skill 的主循环流程，在每轮完成后调用检视：

```
WHILE 迭代计数 <= 最大迭代次数:
  1. 启动 Ralph 子 agent 实现故事
  2. 等待完成
  
  3. **启动检视流程（新）**
     加载 reviewer skill
     执行检视循环（检视 → 修复 → 重新检视）
     只有检视通过才继续
  
  4. 汇报进度
  5. 迭代计数 += 1
```

## 检视标准配置

可以根据项目需要调整检视严格程度。在 `reviewer-config.json` 中配置（可选）：

```json
{
  "strictness": "normal",  // "lenient", "normal", "strict"
  "maxRetries": 3,
  "checks": {
    "acceptanceCriteria": true,
    "codeQuality": true,
    "edgeCases": true,
    "consistency": true
  }
}
```

## 边界情况处理

- **无代码变更**：如果 Ralph 轮次没有产生代码变更，检视直接通过
- **检视 agent 异常**：记录错误，默认视为通过（或根据配置）
- **修复 agent 异常**：记录错误，重试或跳过
- **最大迭代限制**：防止无限循环，建议最多 3 次修复尝试

## 与原版对比

| 特性 | 原版 Ralph | 本实现 |
|------|-----------|--------|
| 质量检查位置 | Ralph agent 内部 | 独立的检视 agent |
| 检查时机 | 提交前 | Ralph 轮次后 |
| 独立性 | 同一 agent | 全新上下文的 agent |
| 修复流程 | agent 自己修复 | 独立的修复 agent |
| 闭环反馈 | 无 | 检视 → 修复 → 重新检视 |
