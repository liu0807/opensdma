# PRD: 命令行数据搬移工具

## 简介

提供命令行数据搬移功能，用户通过命令行指定源地址和目标地址，支持文件路径和内存地址两种地址格式，并支持同步和异步两种执行模式。适用于 MB 到 GB 级别的本地文件系统数据拷贝场景。

## 目标

- 支持通过命令行参数指定源地址和目标地址
- 源地址和目标地址自动识别为文件路径或内存地址格式
- 同步模式下阻塞直到搬移完成并返回结果
- 异步模式下在后台执行搬移，用户可通过命令查询任务状态
- 支持 MB ~ GB 级别的数据搬移

## 用户故事

### US-001: 命令行参数解析与地址识别
**描述：** 作为用户，我可以通过命令行指定源地址和目标地址，工具自动识别地址类型（文件路径或内存地址），以便我无需手动区分格式。

**验收标准：**
- [ ] 支持 `--src` 和 `--dst` 命令行参数指定源和目标地址
- [ ] 自动识别文件路径（如 `/path/to/file`）和内存地址（如 `0x1000`）
- [ ] 参数缺失或格式错误时给出明确的错误提示
- [ ] 支持 `--mode` 参数指定同步（sync）或异步（async）模式，默认同步
- [ ] Typecheck 通过

### US-002: 同步模式数据搬移
**描述：** 作为用户，我可以在同步模式下执行数据搬移，命令阻塞直到搬移完成并显示结果，以便我确认操作成功。

**验收标准：**
- [ ] 同步模式下命令阻塞直到搬移完成
- [ ] 搬移完成后输出结果摘要（源、目标、字节数、耗时）
- [ ] 搬移失败时返回非零退出码并输出错误信息
- [ ] Typecheck 通过
- [ ] 测试通过

### US-003: 异步模式数据搬移与状态查询
**描述：** 作为用户，我可以在异步模式下启动搬移任务并获得任务 ID，随后使用该 ID 查询任务状态，以便在搬移大文件时不阻塞终端。

**验收标准：**
- [ ] 异步模式启动后立即返回任务 ID
- [ ] 支持 `--status <task-id>` 查询任务状态（running/completed/failed）
- [ ] 任务完成后可通过 `--status` 查看结果详情
- [ ] Typecheck 通过
- [ ] 测试通过

### US-004: 进度反馈与中途取消
**描述：** 作为用户，我希望在搬移过程中看到进度信息，并能够在异步模式下取消正在执行的任务。

**验收标准：**
- [ ] 显示已传输字节数和总字节数
- [ ] 显示传输速率和预估剩余时间
- [ ] 支持 `--cancel <task-id>` 取消正在执行的异步任务
- [ ] Typecheck 通过
- [ ] 测试通过

## 功能需求

- FR-1: 命令行接口必须接受 `--src`（源地址）、`--dst`（目标地址）和 `--mode`（sync/async）参数
- FR-2: 源/目标地址自动识别类型：以 `0x` 开头视为内存地址，否则视为文件路径
- FR-3: 同步模式下全程阻塞，完成后输出 JSON 格式结果报告
- FR-4: 异步模式返回唯一任务 ID，任务在后台线程执行
- FR-5: 提供 `--status <task-id>` 查询任务状态和结果
- FR-6: 提供 `--cancel <task-id>` 取消进行中的异步任务
- FR-7: 搬移过程中实时输出进度信息（已传输/总大小/速率/ETA）
- FR-8: 异常处理：源不存在、目标不可写、内存地址不可访问等场景给出明确错误

## 非目标

- 不做跨网络传输（仅限本地）
- 不做数据校验或 checksum 验证
- 不提供 GUI 界面
- 不做数据加密
- 不支持通配符批量搬移
- 不提供配置文件支持

## 技术考虑

- CLI 框架可选：Python argparse / Click，或 Go cobra / Rust clap，取决于项目现有技术栈
- 异步任务管理使用线程池或进程池，任务状态存储在内存中
- 内存地址搬移需考虑平台权限和内存映射安全性
- 大文件搬移使用分块读写以降低内存占用
- 进度反馈通过标准输出实时推送，不依赖外部依赖

## 成功指标

- 同步模式下 MB 级文件搬移耗时在秒级
- 异步模式下启动命令返回时间 < 100ms
- 支持的最大单文件不小于 4GB
- 错误场景覆盖完整，无静默失败
